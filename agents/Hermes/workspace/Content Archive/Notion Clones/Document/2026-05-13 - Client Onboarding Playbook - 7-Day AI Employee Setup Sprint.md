## 7-Day Onboarding Timeline

### Day 0 — Pre-Qualification

Goal: confirm the client is a safe, profitable fit before starting implementation.

### Questions to Ask

- What role do you wish you could hire this month?

- What task wastes the founder/team the most time every week?

- Which tools does your team live in daily?

- What data is sensitive or off-limits?

- Who approves external emails, messages, payments, deletes, posts, or customer-facing outputs?

### Good First Clients

- Founders and operators

- Consultants

- Marketing agencies

- Creators

- Real estate teams

- Education businesses

- Non-regulated SMBs with repetitive admin/research/reporting work

### Avoid First

- Healthcare data

- Finance operations

- Legal privileged documents

- Autonomous payments/refunds

- Clients who want full autonomy immediately without approvals

- Clients with no internal owner

### Day 1 — Paid Kickoff Call, 60 Minutes

Output: choose one AI employee role, one workflow, one success metric, and clear approval gates.

### Kickoff Agenda

- Confirm business outcome

- Pick first agent role

- Map current workflow

- Define approval gates

- Choose tools to connect

- Define success metric

- Agree on 7-day setup plan

### Best Starter Agent Roles

- Founder Executive Assistant

- Sales Follow-Up Assistant

- Research Assistant

- Content Operations Assistant

- Weekly Reporting Assistant

- CRM Cleanup Assistant

> For the first 7 days, we’ll build your Founder Executive Assistant. It will summarize open loops, draft follow-ups, and prepare a weekly briefing. It will not send anything without approval.

### Day 1–2 — Access Collection

Use one simple checklist. Do not ask the client to understand the tool stack. Ask only for access, boundaries, and approvals.

### Collect

- Email/calendar delegated access or approved account

- Project board access

- CRM access if needed

- Company docs/SOPs

- Brand documents

- Approval owner contact

- Preferred reporting channel

### Access Rules

- Never collect passwords in Telegram, Notion, or Obsidian.

- Prefer OAuth or scoped service accounts.

- If password access is unavoidable, use password manager sharing.

- One client = one isolated workspace/vault/credential boundary.

### Day 2–3 — Build the Workspace

Internal implementation. Create the client’s safe operating environment.

### Create

- Orgo workspace / cloud computer or equivalent isolated VM

- Client Obsidian memory folder/vault

- Agent profile/config

- Approved tool connections

- Request/approval board

- Monitoring/watchdog

- Daily/weekly log file

### Suggested Client Folder Structure

- Clients/{Client Name}/00 - Client Brief.md

- Clients/{Client Name}/01 - Access and Boundaries.md

- Clients/{Client Name}/02 - Agent Mission.md

- Clients/{Client Name}/03 - Workflows.md

- Clients/{Client Name}/04 - Approval Rules.md

- Clients/{Client Name}/05 - Weekly Reports/

- Clients/{Client Name}/06 - Logs/

- Clients/{Client Name}/99 - Offboarding.md

### Day 3–4 — Ship One Useful Workflow

Do not build everything. Ship one useful workflow first.

### Good First Workflows

- Daily inbox/open-loop summary

- Weekly founder briefing

- Meeting notes to tasks

- Lead research to CRM draft

- Draft follow-up emails for approval

- Weekly sales/content report

### Definition of Done

- Client sees a real output

- Approval rules are respected

- No risky autonomous action

- Output is useful enough to review

- The agent has a weekly rhythm

### Day 5 — Handoff Demo

Show the client the AI employee working. Keep it simple and trust-building.

### Show

- Where the AI employee lives

- What it can do now

- What it cannot do yet

- How approvals work

- Where reports/logs appear

- How to request new tasks

- How to pause or offboard access

> This is your AI employee’s private computer and memory. It only has access to the tools you approved. For now, it drafts and reports — it does not send, delete, pay, or publish without approval.

### Day 7 — First Useful Report

- First output/report

- Loom walkthrough

- What worked

- What needs tuning

- Next workflow recommendation

### Day 14 — ROI Review

Use the 14-day check-in to turn the sprint into monthly management.

- Did it save time?

- Did it catch anything useful?

- What felt annoying?

- What should we automate next?

- Is this worth expanding into another workflow?

## Approval Gates

### Always Require Approval For

- Sending external emails/messages

- Social publishing

- Payments/refunds/invoices

- Deleting data

- Changing automations

- Deployments

- Accessing large private datasets

- Client-facing advice with legal/financial/medical implications

### Safe Autonomous Actions

- Read approved docs

- Summarize

- Draft

- Categorize

- Create internal notes

- Prepare reports

- Update non-critical internal trackers if pre-approved

## Smoothness Rules

- Send a 5-minute pre-kickoff video explaining the process.

- Give clients one checklist, not five documents.

- Default first agent = Executive Assistant unless another role is obvious.

- Keep kickoff focused on one workflow only.

- Show something useful within 72 hours.

- Use Loom so clients see the AI employee actually working.

- Make every task request go through one channel/board.

- Over-communicate boundaries: draft-only first, approvals for external actions.

## Example First-Week Scope

- Client: service business founder

- AI employee: Founder Executive Assistant

### Week 1 Workflows

- Summarize inbox/open loops daily

- Turn meeting notes into tasks

- Draft follow-up emails for approval

- Prepare Friday weekly briefing

### Success Metric

- Save founder 3–5 hours/week

- Reduce missed follow-ups

- Deliver one weekly report every Friday

### Approval Rules

- May draft emails

- May create internal tasks

- May not send emails

- May not delete or change CRM records without approval

## One-Line Operating Principle

> Don’t make the client think. Give defaults, ask only for decisions that affect business priority or safety, and deliver one useful output fast.
