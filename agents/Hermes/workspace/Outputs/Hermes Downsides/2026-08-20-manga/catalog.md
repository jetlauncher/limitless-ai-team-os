**Format:** 11 slides, 1920×1080  
**Evidence basis:** Jet × Kelly operating history, current multi-profile cron health, August usefulness reset, integration and model-routing incidents.

## 01 — Cover
**The Downsides of Hermes**  
What real use taught us.  
**Core line:** Power without discipline creates a second job.

## 02 — The Real Problem
Hermes makes it easy to build more AI activity than business outcomes.
- Capability grows quickly.
- Coordination grows with it.
- Outcomes do not grow automatically.

**Bottom line:** An impressive AI organization can still fail to create freedom.

## 03 — The Complexity Tax
Current operating evidence:
- 123 jobs scanned across profiles.
- 32 jobs active.
- 494 default-profile cron output files generated in one week.

**Bottom line:** Eventually, maintaining the system becomes another system to run.

## 04 — Busy Is Not Useful
Busy output:
- Scans
- Drafts
- Dashboards
- Recommendations
- Maintenance artifacts

Useful outcomes:
- Shipped
- Used
- Sold
- Decided
- Risk prevented

**Bottom line:** A report is not an outcome until someone uses it.

## 05 — Integrations Drift
Recurring real-world failure points:
- OAuth tokens expire.
- APIs change.
- Interfaces move.
- Delivery routes break.

**Bottom line:** Third-party dependencies age even while Hermes itself is healthy.

## 06 — False-Green Health
A job can say `OK` while the output contains:
- 401 Unauthorized
- Expired token
- Traceback / error
- Stale last run

**Verification chain:** Process running → output healthy → delivery confirmed → result useful.

## 07 — Context and Memory Burden
More tools, skills, notes, profiles, and history can produce:
- Context compaction
- Skill reloads
- Stale or duplicate memory
- iCloud file locking
- Slower prerequisite checks

**Bottom line:** Memory can become an organized junk drawer without hygiene.

## 08 — Multi-Agent and Model Risk
More agents can create:
- Duplicate schedules or credentials
- Overlapping work
- Ambiguous ownership
- Silent model fallback
- Quality or persona degradation

**Bottom line:** Configured model does not always prove the model that handled the session.

## 09 — The Fragile Final Mile
- GUI automation breaks when layouts change.
- Broad access increases safety responsibility.
- Public, destructive, credential, billing, and financial actions require human approval.

**Operating principle:** Prefer APIs over GUIs. Keep human judgment above the system.

## 10 — Keep, Reduce, Route
### Keep in Hermes
- Memory and routing
- Business-wide workflows
- Approvals and delivery
- Automation health

### Reduce
- Generic scans
- Duplicate dashboards
- Unreviewed content
- Ownerless agents

### Route to specialists
- Claude Code: deep implementation and debugging
- ChatGPT/Codex: parallel builds, artifacts, review

## 11 — The Rule
Every recurring workflow must do at least one:
1. Save time
2. Make money
3. Reduce risk
4. Improve a decision

If it does none of these: **pause it**.

**Final verdict:** Keep Hermes. Make it smaller, sharper, and accountable.
