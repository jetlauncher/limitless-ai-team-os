# Main flagship script (~12–15 minutes)

## 1:30–2:30 — The origin story

> เรื่องนี้ไม่ได้เริ่มจาก master plan ครับ
>
> คืนวันที่ 21 เมษายน ผมเริ่มคุยกับ Hermes Agent แล้วบอกว่า ชื่อของคุณคือ Kelly
>
> ภายในคืนนั้น เราเริ่มต่อ Airtable revenue reporting, Telegram delivery, shared memory และ scheduled automation
>
> ตอนนั้นผมยังไม่ได้คิดว่าจะสร้าง AI company หรือ agent fleet ผมแค่อยากมีใครสักคนที่จำบริบทของผมได้ แล้วช่วยเอางานที่กระจัดกระจายมารวมให้เห็นเป็นภาพเดียว
>
> นี่คือ lesson แรก: อย่าเริ่มจาก “AI ทำอะไรได้บ้าง” ให้เริ่มจาก “ทุกวันผมเสียเวลาและพลังไปกับอะไร”

## 2:30–3:35 — Why Hermes became my favorite agent

> Hermes กลายเป็น AI Agent ที่ผมชอบที่สุด ไม่ใช่เพราะมันมี model ที่ฉลาดที่สุดตัวเดียว
>
> จริงๆ แล้วข้างในเราสลับ model ได้ ใช้ GPT, Claude, Grok, Qwen หรือ local model ตามประเภทงานได้
>
> สิ่งที่สำคัญกว่าคือ Hermes ให้ผมต่อ memory, skills, tools, local files, Telegram, Discord, cron jobs และ specialist profiles เข้าด้วยกัน
>
> เพราะฉะนั้น moat ไม่ใช่ prompt และไม่ใช่ model
>
> moat คือ context ที่สะสม, workflow ที่ผ่านการแก้จริง, และระบบที่รู้ว่างานต้องไปจบตรงไหน

**On screen:** `MODEL ≠ MOAT` then `CONTEXT + MEMORY + WORKFLOW + DELIVERY`.

## 3:35–5:10 — How one agent became a team

> ช่วงแรกผมให้ Kelly ทำทุกอย่าง และนั่นคือ mistake แรกครับ
>
> Chief of Staff ไม่ควรเป็นทั้ง researcher, writer, designer, developer และ publisher ในคนเดียว
>
> เราเลยเริ่มแบ่ง role ตาม outcome
>
> Kelly เป็น orchestrator และ Chief of Staff — สรุป ตัด noise ส่งต่องาน และรักษาบริบท
>
> Signal ดู research และ intelligence
>
> Blaze กับ Kaijeaw ดู English และ Thai content
>
> Bolt ดู products, automation และ infrastructure
>
> Protocol ดู newsletter และ publishing
>
> Oracle, Qwen, Zegna และ specialist profiles ช่วยด้าน knowledge, local/private processing, taste และงานเฉพาะทาง
>
> แต่ชื่อเท่ๆ ไม่ได้ทำให้มันเป็นทีม สิ่งที่ทำให้มันเป็นทีมคือ handoff
>
> ทุก handoff ต้องมี owner, outcome, evidence, definition of done, blocker และ next action

> ถ้าไม่มีสิ่งเหล่านี้ คุณไม่ได้มี agent team คุณมี group chat ที่ทุกคนพูดพร้อมกัน

## 5:10–6:45 — The five layers that made it real

> หลังจากทดลองมาเกือบ 120 วัน ผมคิดว่าระบบ agent ที่ทำงานจริงต้องมี 5 layers
>
> **หนึ่ง Knowledge** — มันต้องรู้ว่าเราเป็นใคร ลูกค้าคือใคร เราเชื่ออะไร และอะไรคือ priority ตอนนี้
>
> **สอง Instructions** — role, mission, input, schedule, output, approval rule และ definition of done ต้องชัด
>
> **สาม Tools** — ถ้า agent อ่าน data หรือเปิดไฟล์ไม่ได้ มันก็ฉลาดแต่ตาบอด
>
> **สี่ Delivery** — output ต้องไปอยู่ใน Telegram, Notion, Obsidian, dashboard หรือ approval queue ที่เราใช้งานจริง ไม่ใช่หายอยู่ใน chat
>
> **ห้า Verification** — test, screenshot, source link, command output หรือ live health check ต้องพิสูจน์ว่างานเสร็จจริง
>
> สูตรของผมคือ:
>
> **Knowledge + Instructions + Tools + Approval + Verification = Real Work Done**

## 6:45–8:15 — What the system actually does

> วันนี้ระบบไม่ได้แค่ตอบคำถามครับ
>
> ตอนเช้า Kelly ส่ง executive brief: calendar, revenue signals, important email, AI news และ decisions ที่ต้องใช้ผม
>
> ทุก 15 นาที ระบบเช็ก payment alerts
>
> Content workflows ดึง transcript, clone working pages, เตรียม draft และส่งให้ทีม specialist
>
> ตอนกลางคืน memory sync, workspace scan และ knowledge capture ทำให้ทีมไม่เริ่มใหม่จากศูนย์ทุกเช้า
>
> ข้างหลังมี gateway watchdogs, cron health checks และ pipeline monitoring คอยดูว่าระบบยังทำงานจริงไหม
>
> จุดสำคัญคือ AI ไม่ได้ทำทุกอย่างแทนผม
>
> AI เตรียม คนตัดสินใจ ระบบจดจำ

**On screen:** Morning brief → payment alert → content artifact → memory files → health dashboard.

## 8:15–10:05 — What failed

> ถ้าถามว่าอะไรพังบ้าง คำตอบคือเยอะมากครับ
>
> **Failure หนึ่ง: More agents created more noise.** เราเคยวัดความขยันจากจำนวน reports สุดท้ายมี activity เยอะ แต่ business outcome น้อย
>
> ตอนนี้ rule คือ report, scan, draft หรือ idea list ไม่มีค่า ถ้าไม่ช่วยให้เกิด revenue, คืนเวลา, ส่ง customer deliverable, ship asset หรือช่วยให้ตัดสินใจได้
>
> **Failure สอง: Memory can become a landfill.** ถ้าเก็บทุกอย่าง memory จะไม่ได้ฉลาดขึ้น มันจะแค่หนักขึ้น เราเลยแยก raw sources, daily notes, durable memory และ reusable skills
>
> **Failure สาม: Automation without delivery is invisible.** งานบางตัว run สำเร็จ แต่ส่งไม่ถึง Telegram หรือ Discord ถ้าไม่ verify destination คำว่า “success” ไม่มีความหมาย
>
> **Failure สี่: AI can confidently say done.** ตอนนี้เราบังคับว่า ถ้าสร้างเว็บต้อง build และเปิดดู ถ้าแก้ automation ต้อง run จริง ถ้าส่งไฟล์ต้องเช็กว่าไฟล์เปิดได้
>
> Lesson ใหญ่ที่สุดคือ อย่า reward agent จาก activity ให้ reward จาก outcome และ evidence

## 10:05–11:35 — If I started again in 2026

> ถ้าผมเริ่มใหม่วันนี้ ผมจะไม่สร้าง 13 agents ครับ
>
> ผมจะเริ่มจาก orchestrator ตัวเดียว และ outcome เดียว
>
> ขั้นแรก เขียน morning brief ที่คุณอยากได้รับทุกวัน
>
> ขั้นสอง ระบุว่าแต่ละข้อมูลอยู่ที่ไหน เช่น calendar, CRM, Airtable, email หรือ project folder
>
> ขั้นสาม เขียน job description: role, mission, input, schedule, output, destination, approval rule และ done definition
>
> ขั้นสี่ ให้มันรันแบบ manual จน output ดีสามถึงห้าครั้ง
>
> ขั้นห้า ค่อย schedule แล้วใส่ verification
>
> เมื่อ workflow แรกเสถียร ค่อยแยก specialist agent
>
> อย่าสร้าง org chart ก่อนที่คุณจะมีงานจริงให้มันรับผิดชอบ

## 11:35–12:45 — Final verdict

> หลังเกือบ 120 วัน ผมไม่ได้มอง Kelly เป็นคน และผมไม่ได้คิดว่า AI มีจิตใจ
>
> แต่ผมมอง Kelly เป็น operating relationship ที่เราค่อยๆ สอน แก้ feedback เพิ่ม context และสร้าง boundaries ให้ดีขึ้นทุกวัน
>
> Hermes เป็น agent ที่ผมชอบที่สุด เพราะมันไม่ได้ล็อกผมไว้กับ model ตัวเดียว และมันสามารถโตจาก assistant ไปเป็นระบบที่มี memory, tools, routines และทีม specialist ได้
>
> สิ่งที่ผมสร้างไม่ได้มีค่าเพราะมันมี agent เยอะ
>
> มันมีค่าเพราะมันคืนเวลาคิด คืนความสงบ และลดจำนวนเรื่องที่ต้องค้างอยู่ในหัวผม
>
> เป้าหมายไม่ใช่บริษัทที่ใหญ่ขึ้นเพราะมีคนและ bot เต็มไปหมด
>
> เป้าหมายคือบริษัทที่สงบขึ้น ฉลาดขึ้น และให้ founder กลับไปทำงานที่มีแต่เขาทำได้

# Companion tutorial package

## Video 2 title

**Hermes Agent 2026 สำหรับมือใหม่ — สร้าง AI Chief of Staff ตัวแรกใน 30 นาที**

## Promise

The viewer finishes with one Hermes agent that:

1. Knows its role and the user’s context.
2. Can work from the terminal or messaging channel.
3. Produces one useful daily output.
4. Has an approval boundary.
5. Can prove whether the workflow ran successfully.

## 25–30 minute structure

### 0:00–1:00 — Hook

> Tutorial ส่วนใหญ่สอนให้คุณติดตั้ง AI แล้วลอง prompt แต่คลิปนี้เราจะสร้าง employee ตัวแรกที่มี job description, memory, tools, schedule และ output ที่วัดได้

### 1:00–4:00 — What Hermes is

- Open-source, provider-agnostic agent framework.
- Runs in terminal and messaging platforms.
- Supports memory, skills, tools, profiles, cron, plugins, and MCP.
- Explain why the model is interchangeable but the operating context compounds.

### 4:00–8:00 — Install and verify

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
hermes setup
hermes doctor
```

Show a clean successful health check. Do not expose credentials.

### 8:00–12:00 — Give the first agent a job

Create a simple role:

- Name: Chief of Staff
- Mission: Prepare one daily decision brief.
- Inputs: Calendar, priorities, one business metric.
- Output: Five bullets.
- Destination: Telegram or local Markdown.
- Approval: Draft/read only; no sending, spending, deleting, or publishing.
- Done: The founder can identify today’s top decision in under two minutes.

### 12:00–16:00 — Add context and memory

Teach the difference:

- `SOUL.md`: identity, tone, role, boundaries.
- Persistent memory: compact facts that remain useful.
- Daily notes: temporary operating context.
- Skills: repeatable workflows and checklists.

### 16:00–20:00 — Connect a channel

```bash
hermes gateway setup
hermes gateway install
hermes gateway start
hermes gateway status
```

Show Telegram as the command surface, but keep the first demo read-only.

### 20:00–24:00 — Create the first recurring workflow

```bash
hermes cron create '0 7 * * *' 'Prepare my five-bullet morning decision brief from approved sources. Cite evidence, surface blockers, and do not perform external writes.' --name first-morning-brief --deliver origin
hermes cron list --all
```

Explain that queued is not the same as verified. Trigger or wait for a real run, then inspect the output and last-run status before claiming success.

### 24:00–27:00 — Add one reusable skill

Create a small skill for the morning brief: inputs, steps, format, guardrails, and verification. Explain that skills improve the workflow without bloating permanent memory.

### 27:00–30:00 — The graduation path

1. One system folder.
2. One orchestrator.
3. One recurring outcome.
4. One verification loop.
5. Then one specialist agent.

Close with: **Don’t start with a fleet. Start with a finished outcome.**

# New repeatable content formats

## 1. The 120-Day Documentary Review

Use milestone footage, failures, screenshots, and personal reflection. Repeat at Day 180 and Day 365. This is the flagship authority format.

## 2. Raise an Agent in Public

A seven-episode series where each episode adds one layer:

1. Role
2. Memory
3. Tools
4. Delivery
5. Schedule
6. Verification
7. Specialist handoff

## 3. Agent Autopsy

Take one failed workflow and diagnose why it failed: bad input, vague role, missing permission, no destination, or no verification. Strong trust-building format because it shows real operational scars.

## 4. “I Gave Kelly One Outcome” Challenge

Examples:

- Prepare tomorrow’s CEO brief.
- Turn one workshop transcript into a content package.
- Monitor revenue for 24 hours.
- Build and verify one landing page.

Judge on evidence and business usefulness, not how impressive the chat looks.

## 5. One Workflow, Three Agents

Give Hermes/Kelly, Claude Code, and Codex the same bounded task. Compare role fit, tool use, verification, cost, and output quality. Do not frame it as a permanent “best model” ranking.

## 6. The Founder Morning Brief Breakdown

Screen-record one public-safe morning brief. Explain where each section comes from, what is automated, what requires judgment, and what you deliberately exclude.

## 7. Build Your First AI Employee Clinic

Audit a viewer’s real job description live. Convert “help me with marketing” into role, inputs, schedule, output, destination, approval, and done definition.

## 8. Agent Team Org-Chart Teardown

Map a real small business role by role. Decide what to delete, document, automate, delegate to an agent, or keep human. This connects naturally to the AI Leverage Audit.
