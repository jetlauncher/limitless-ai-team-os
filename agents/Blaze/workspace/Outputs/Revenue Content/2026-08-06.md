## Final publish-ready Thai script

AI ที่ทำงานเก่ง แต่ไม่มีขอบเขตสิทธิ์ ไม่ใช่พนักงานครับ—มันคือความเสี่ยงที่ต่อ API ไว้แล้ว

วันที่ 5 สิงหาคม Cloudflare เปิดตัวระบบมองเห็นการใช้ AI แยกตามตัวตน และทดลองเครื่องมือคุมการเขียนข้อมูลผ่าน MCP

ในระบบภายในของเขา Agent ตรวจเจอปัญหาที่อาจเกิดขึ้นเกือบ 250,000 จุด และบล็อกการ merge ไป 16,000 ครั้งใน 4 เดือน

บทเรียนไม่ใช่ “เลิกใช้ AI” แต่คือ **อย่าให้สิทธิ์ Action ตั้งแต่วันแรก**

ผมสอนเรื่องนี้ในคลาส OpenCore ด้วย Guard Rails ที่ชัดมาก:

- **Read** — ให้อ่านและสรุป
- **Draft** — ให้เตรียมงาน แต่คนตรวจ
- **Action** — ส่ง โพสต์ จ่ายเงิน หรือลบข้อมูลได้ เฉพาะเมื่อมีเจ้าของงานและกฎอนุมัติ

และนี่ไม่ใช่แค่ทฤษฎี เมื่อวานเราเพิ่งหยุดระบบโพสต์ Threads อัตโนมัติ งาน Draft ยังเดินต่อได้ แต่การ Publish ต้องรอผมอนุมัติใหม่

ก่อนเพิ่ม Agent ตัวต่อไป อย่าถามแค่ว่า “มันทำอะไรได้”

ให้ถามด้วยว่า **มันแตะระบบไหนได้ ใช้เงินได้เท่าไร ใครอนุมัติ และย้อนกลับอย่างไร**

นี่คือจุดที่ AI เปลี่ยนจากของเล่น เป็นระบบธุรกิจที่ผู้บริหารไว้ใจได้
